# v0.4 — the skillset lockfile is committed; skill files restore from it

`.reinicorn/skillset-lock.json` is the project's declared methodology:
commit it (projects created with v0.3 that gitignored it should drop that
rule). The adapter-installed skill files may stay gitignored — a clone
with the lock and no files is now a repaired state, not a broken one.

## Skills

- `rcorn skills install` with no argument restores the adapter the
  lockfile records: fetches its pin, writes back only the missing files
  (each verified against the lock's hash), regenerates the wiring doc and
  the compatibility link. Files that exist are never touched.

## What happens on `rcorn update`, `rcorn init`, and checkout

- `rcorn update`, the hooks-only `rcorn init` (teammate clone), and the
  post-checkout hook run the same restore when lock-recorded files are
  missing. Silent when nothing is missing; a failed restore (offline, a
  lock that no longer matches its adapter) is reported and never fails
  the command or the checkout — re-run `rcorn skills install` later.

## Breaking changes

- None. A project that committed both the lock and the files sees no
  change; one that gitignored the lock keeps working until it un-ignores
  and commits it, which is now the documented setup.
