# v0.4 — the process is config

The document types, what they depend on, what closes what and what must be
filled in before a plan can complete are now yours to change in
`kb/<scope>/doc-types.yaml`. Without that file you get the shipped set,
and everything below applies to it.

## Commands

- New `rcorn doc-types show` prints the effective registry, each row marked
  `built-in` or `overlay`; `--schema` emits a JSON Schema for the overlay.
  README "Customizing the process" has the override / add / disable
  semantics and an RFC → ADR worked example.
- `rcorn plan complete` now refuses when the retro is missing or still the
  placeholder scaffold (it used to warn). `--abandon` drops the plan
  without a retro. The post-merge sweep no longer archives a plan without
  one; its refusal and next step appear in the merge output.
- `rcorn plan complete` and `plan status` are generated from the registry:
  any type that another type `closes` gets the same two verbs.

## Defaults that changed

- The retro is required: `retro.closes` is `{type: plan, required: true}`.
- The retro template gains a fifth required section, `Spec Drift`: every
  deviation between the plan's declared `spec:` and what shipped, each
  amended, debted or accepted, or the single word "None."
- Opt out of either in the overlay (two lines; see the README section).

## Lint rules (all seeded at error severity)

- `kb/required-sections` replaces `kb/plan-structure` (still accepted as an
  alias) and checks every type with `required_sections`.
- `kb/draft-refs` now follows every `depends_on` relation, not only
  plan → spec.
- New `kb/closer-filled`: a retro (or any required closer) left as the
  placeholder scaffold.
- New `kb/lifecycle`: a plan still active after its branch merged or was
  deleted.

## CI

- `rcorn _process-gate <branch>` runs the branch-scoped subset
  (`required-sections`, `draft-refs`, `closer-filled`, with a missing closer
  counting) and prints the effective registry; the reinicorn repo runs it as
  the "Process gate" PR check. Wire it into your own PR workflow if you want
  the same bar.
